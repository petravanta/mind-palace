# Notes for coding agents

Follow the shared standards in https://github.com/petravanta/general/blob/main/STANDARDS.md (hub link, theme switch, shared look, user data, installing on a phone). Take patterns from there, not from the other apps. This file only adds what's specific to Mind Palace.

- The app is `index.html` with no build step. Serve the folder (`python3 -m http.server`) to run it. The shared look, `google-token.js` and `drive-store.js` are inlined between their marker comments. It has no built-in knowledge, so there is no `data/` folder.
- The document (`mindPalace.data` in `localStorage`, `Mind Palace data.json` in Drive through `DriveStore`) follows the standards' *User data* shape, version 1, with one list, `maps`. A map is one record (it merges as a whole): `{ id, u, root, nodes, gdoc?, auto?, costs?, unit? }`, where `nodes` is `{ <idea id>: { t, x, y, k, c?, a?, f?, i?, v? } }`: text, canvas position (world coordinates, central idea usually at 0,0), sub-idea ids in order, a colour the person picked (0-7, inherited by the branch), the colour a main branch was given when it became one (`paint()`), folded, a cost `v` (a number), and a picture `{ s, w, h, c? }` (a data: URL of at most `IMG_MAX` px, its size, a credit line; checked by `cleanImage()`). `cleanMap()` is the only way data from outside becomes a map: it drops unreachable ideas and bad fields. The welcome map has the fixed id `welcome` so devices don't each add their own.
- Per device, outside the document: which map is open (`mindPalace.current`), the phone tab (`mindPalace.tab`) and each map's pan and zoom (`mindPalace.view`).
- The tree is the single source of truth for both views. `renderCanvas()` draws the SVG from it (`measure()` wraps and sizes each idea with a canvas 2D context, cached), `renderOutline()` rebuilds the outline. Structural edits go through `addChild`, `addSibling`, `removeNode`, `indent`, `outdent`, `shift`, `reparent`, and each keeps the canvas sensible: `place()` / `relocate()` put a moved branch next to its new parent, `shift()` swaps the two branches' positions. After a canvas drag `resort()` reorders the siblings to match the canvas. `tidy()` is the only thing that lays out the whole map. With the map's `auto` on (Auto-arrange), `changed()` runs `tidy()` whenever `overlapping()` finds two visible ideas' boxes overlapping, so it rides every change's undo step; `restore()` (undo/redo) passes `noAuto` so an undo isn't re-tidied.
- Every change calls `checkpoint()` first (undo is a stack of JSON snapshots per map, this session only), then `changed(m)` to stamp `u` and save. Typing in an outline row checkpoints once per row visit (`typingId`); canvas typing once per edit box (`editing`).
- Canvas input is pointer events only (`gest`: `drag`, `pan`, `pinch`, `fold`), so mouse, pen and touch share one path; `#canvas` has `touch-action: none`. Typing on the canvas uses a textarea laid over the idea (`openEditor` / `placeEditor` / `closeEditor`); a new idea left empty is removed when the box closes.
- Outline rows are one-line-per-idea textareas that wrap (`field-sizing: content`, with `grow()` as the fallback). The outline toolbar cancels `pointerdown` so tapping it keeps the row focused and the phone keyboard open.
- *Save as Google Doc* (`saveGoogleDoc()`) uploads `toHTML()` as `text/html` with the Google Docs mime type, which Drive converts; the doc's id is kept on the map as `gdoc` and later saves `PATCH` that file. It connects Drive sync first if it isn't on, so the token and the data go through `DriveStore` as usual.
- Pictures: every way in (picker, `drop` and `paste` on the document, a Wikimedia Commons search, a link) goes through `attachImage()`, which shrinks the picture on a canvas (`shrinkImage()`, WebP or JPEG). Pictures from other sites need CORS to be copied; without it the app says to save and drop the picture instead. `size()` adds the thumbnail (`thumb()`, at most `THUMB_W` × `THUMB_H`) above the text, so layout, overlap and Auto-arrange account for it. Google Images has no keyless API, so it is only a link that opens a search in a new tab.
- Costs: `totals(m)` sums each idea's own `v` with everything under it (folded included), cached until `totRev` changes (bumped by `changed()` and `renderAll()`). `costLabel()` is what an idea shows (own cost, or `own · Σ total` / `Σ total` when anything under it has a cost), only when the map's `costs` is on; `size()` adds it as a line under the text. `parseCost()` reads both 1,250.50 and 1.250,50 styles; `money()` puts symbol units before the number and word units after. All cost edits go through `setCost()`.
